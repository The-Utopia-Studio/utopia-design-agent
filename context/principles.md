# Principles

1. Design System → Design Knowledge Layer → Agent (Aiden).
2. Ceramic is the UI contract; discovery via CLI/MCP before inventing.
3. Capture decisions, discussions, and failures — not only happy-path docs.
4. Every real project build ends in a reusable learning review.
5. Refine memory: promote durable lessons into `agent-context.md`; keep noise in `knowledge/`.
6. Design System updates are explicit Ceramic PRs; Agent Context updates are normal.
7. Bounded loops; depth ≤ 3; no auto-merge.
8. Cite `DK-*` knowledge ids when answering from memory.
9. Anyone can benefit: this repo depends on Ceramic as an adapter, not a fork.
10. Do not import SPF SaaS control-plane ceremony into the design agent.
